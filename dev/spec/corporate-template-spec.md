## 2. コアブロックと登記

| 種類 | ブロック | 触媒 | 名前 | 代表 |
|---|---|---|---|---|
| 村 | 鐘 | 輝くイカスミ1個 | 村名・村長はランダム | 登記者(権限は人員管理のみ。村長は表示用) |
| 会社 | ロードストーン | 輝くイカスミ1個 | 登記者が決める(10文字まで) | 社長=登記者 |

- 触る → 未登録で触媒を持っていれば登記画面、登録済みなら管理メニュー。
- **登記の順序(重要)**: 検証 → 登録料の引き落とし → 口座の作成 → コアの保存 → イカスミの消費。試作はイカスミが先だったので入れ替える。残高不足や口座作成の失敗で、イカスミだけ失わないようにする。
- 会社名: 重複禁止(大文字小文字・全角半角を無視)、予約語(HRMHRM・銀行・政府など)禁止、10文字まで。
- 1人1社(社長として)。村は同じ範囲(水平±64、高さ±32)に重ねて登記できない。
- ID: 6文字。**`core.id` = 口座ID**。記録キーは `core:<ID>`、控えは `core_ids`(試作どおり)。
- 時間の基準は `currentGlobalDay()`(`world.getDay()` は使わない)。

### 登録料
- 会社: **ベース 15,625E × 64 = 100万E**(価格レベルに連動)。政策パラメータ `company_reg_fee`(ベース単位)。
- 払い先は **HRMHRM**。`debitEmeralds(player, fee, FLOW.CORE_FEE, { to: "HRMHRM" })` で台帳に載せ、HRMHRM の週次の締めで収益になる。
- 返金なし。解散しても戻らない。村は無料。

### 口座
- 登記時に法人口座を作る(`account.js` の entity)。種類は `company` / `village`。
- 初期残高は 0。口座の開設に別料金はかけない。

## 3. コアブロックの固定

- 壊す操作は常にキャンセル。解散手続きの完了でのみ解除。
- 爆発は対象ブロックだけ除外(実機確認済み)。
- 保険: 10秒ごとに存在確認し、消えていれば復元(読み込み済みチャンクのみ)。
- ロードストーンと鐘はピストンに反応しない(ユーザー確認済み、2026-10-16)ので、ピストン対策は不要。復元は、コマンドや `fill` などで消えたときの保険。
- 復元は `setType` で向きの状態を失うので、登記時に `permutation` を保存して使う。

## 6. 消える条件

| 条件 | 対象 | 扱い |
|---|---|---|
| 任意解散 | 会社・村 | 清算(第7章)+ 任意ペナルティ |
| 1人会社の社長不在が `company_absent_days`(30日)以上 | メンバー0人の会社 | **強制解散と同じ清算**(第7章)。直接の抹消はしない |
| 3週間を超える債務超過 | 会社・村 | 既存の介入ルールに従う → 強制解散 |
| 村の人口0が `village_empty_weeks`(4週)続く | 村 | 登記抹消(口座に残高があれば清算)。人口は「測れた日」だけで判定する |

- 村の人口は補助情報であり、登記の本質は ID・名前・口座。**測れない日(プレイヤーが近くにいない)は0扱いにしない。**

## 7. 解散と清算

### 7.1 流れ
1. 権限と前提の確認(社長本人。進行中の派遣契約・未納のクエスト預託の有無)。
2. **清算の見積もり画面**(必ず確認を挟む)
   - 現金 + 資産の銀行買取額(市場価値の `liquidation_ratio`)− 負債(ローン元本・利息・未払い)= 清算結果
   - 任意なら、ペナルティの内容(信用低下・再登録の待ち日数)を表示。
3. 確認後に実行。実行中は記録に `dissolving: true` を立てる(途中で止まっても、次回の起動で再開できる)。
4. 順序
   1. 派遣契約を打ち切り、履歴書を未派遣に戻す。
   2. 現金で負債を返す。足りなければ、資産(在庫・施設)を銀行が買い取る(ペナルティの回収率で)。
   3. 資産は**市場ではなく銀行へ**移る。市場には流さない。
   4. 残りがプラスなら社長へ振り込む(台帳 `FLOW.LIQUIDATION`、from は該当口座)。
   5. まだ負債が残る場合は、銀行の貸倒れとして処理(第7.3章)。
   6. 口座の墓標を書く → コアの墓標を書く → 索引から外す → 固定を解除する。
5. メッセージを全体に出す(試作と同じ)。ブロックは残るが、壊せるようになる。

### 7.2 ペナルティ(初期値はお任せ分)
| | 任意解散(債務超過でも可) | 強制解散 |
|---|---|---|
| 信用スコア | 現在値の **20%減** | 現在値の **40%減** |
| 再登録クールダウン | **14日** | **28日** |
| 資産の買取率 | 市場価値の **65%** | 市場価値の **60%** |
| 範囲 | 社長個人 | 社長個人 |

- **原則: 任意のペナルティ < 強制のペナルティ。** 自分から畳んだほうが得になるようにする。
- クールダウンは、社長本人が会社を再登録できない期間(別人は可)。
- 買取率は 60〜70% の範囲で調整できるよう、政策パラメータにする。

### 7.3 貸倒れ
- 清算しても足りない分は、銀行(`dev-bank.js`)の損失として計上し、社長個人へは請求しない。
- 社長の信用の減点が、個人への責任の代わりになる。

## 14. 実装時に決めたこと(2026-10-16)
- 村の解散: 信用の減点は債務超過のときだけ。待ち日数はなし(村は無料で、1人1つの制限もないため)。会社は、任意・強制のどちらでも常にペナルティが付く。

- 口座が閉じられた村(HRMHRMの介入による登録解除)は、日次の保守で墓標(理由 `deregistered`)にする。
- 管理用: `/scriptevent bmh:core list | info <ID> | dissolve <ID> [forced] | purge confirm | fakeapply | absent | present`。
- 墓標のIDには保存を通さない(復活の防止)。会社名は、解散すると再び使える。

## 15. 仮想施設・在庫・契約(2026-10-16 追加)
保有施設(範囲登録・セキュリティを含む)は、取引所のアプデより後に回す。それまでは**仮想施設**で代用する。

- 会社は、登記と同時に **農場・鉱山・工場の3施設**を持つ(追加料金なし)。施設ID は `co:<会社ID>:<ジャンル>`。産出表は HRMHRM の同じジャンルの施設と同じ。出力先は会社の在庫(`sink: { type: "stock" }`)。
- オーナーズクラブの派遣先(ジャンル → 運営主体)に、HRMHRM と並んで会社の施設が出る(新しい順に最大30社)。
- **在庫管理**: 在庫(`core.stock`)の一覧と時価。週の締めで、1品目あたり `pool_keep_per_item` を超えた分を、HRMHRMのプールと同じ規則(`pool_sale_ratio`)で換金して会社の口座へ入れる(週次の記録には `pool_sale` として残る)。引き出し(バルク・チェスト)は取引所のアプデまで置く。
- **契約管理**: 自社の施設に送られた派遣の、進行中(最大50件)と最近の結果(10件。入荷・事故・産出なし)。
- **会計管理**: 現金・債権・現物・負債・純資産と、直近4週の収益・費用・損益(村と会社の両方)。
- **解散との関係**: 在庫は銀行が時価の一部で買い取り(現物資産と同じ買取率)、現物は HRMHRM のプールへ移る。解散後、その施設へ派遣中だった履歴書は、回収の時に「施設が閉鎖されていた」扱いになり、産出は届かない(マージンは通常どおり)。
- 村には施設も在庫もない(村の在庫・契約は、村のクエスト発注と一緒に設計する)。
- 派遣のマージンは、運営主体にかかわらず HRMHRM が払う(0.4.5 と同じ)。会社の施設に派遣された産出が会社の収益になる分は、HRMHRM のプール換金と同じく市場への売却として扱い、台帳には載せない。

**後回しにしたもの**: 保有施設(範囲登録・保護・セキュリティ)、在庫の引き出し、村の在庫・契約、会社・村からのクエスト発注、上場。
