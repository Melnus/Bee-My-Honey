# 取引所の仕様(0.5.6〜0.6.x。2026-11-03)

(旧スケッチ「sketch-exchange」。実装済みのため削除) の決定事項と、作者のモック画面(2026-11-02)・会話で決まった内容をまとめた。**決定**・**実装済み(0.5.6)**・**次**・**未決**を分けてある。

## 画面の構成(決定。モック)
- 入口: 今の郵便販売(書見台 + 紙)を置き換える。トップ: 物品別リスト / 出荷一覧 / 入荷一覧 / 本日のオススメコーナー / カスタマーサービス / リーガルサービス。
- 物品別リスト: 生鮮物 / 一般資源 / 希少資源 / 無形資産 → 品目のページ(出品者・数量・単価。最安値の出品から自動で選ばれる)→ 購入画面。郵便販売のカタログの品は、一般資源・各ジャンルに入れる。
- 出荷一覧: 自分が出品する窓口。専用シュルカーから、品を取引所プールへ入れて、出品する。
- 入荷一覧: 買った品。専用シュルカーへ届く(**入荷・出荷には専用シュルカーが必須**。0.5.5)。
- オススメ: ランダムな品、または期限が近くてお買い得な品。
- カスタマーサービス: カード管理・プライム(郵便販売にあった設定がそのまま移る)。リーガルサービス: カメさんの相談窓口。

## お金と品物の流れ(決定)
- **取引所プール(ユーザー固有)**: 専用シュルカーから取り込んだ品は、いったんここに入る。出品した分はプールから出品に移る(二重売りを防ぐ)。取り下げ・期限切れで、残りはプールへ戻る。
- **輸送費**: 出品時に、出品額(数量×単価)の何%を出品者が払う(返金なし)。成約手数料は物品では取らない。本来プレイヤーが運び屋に払う運賃を、手数料に省略したもの。
- **取引所の専用口座**(id `exchange`、種類 `exchange`): 輸送費・保証金・手数料の受け口。補填もここから払う。足りなければ開発銀行機構が支給する(介入の対象外)。
- **価格**: HRMHRMの常設出品(基準価格 × 1.25 × 掛率。実在庫制・毎日補充)が、購入側の上限。プレイヤーの出品は、その価格以下で自由に付ける。
- **購入**: 安い出品から自動で選ぶ(同じ価格は古い順)。自分の出品は買えない。代金は口座残高から(カードは次)。
- **無形資産(次)**: 紙・本を出品し、説明欄に書いたこと自体を売る。軽いオークション。保証金を取り、双方が「取引成立」を押すと行き渡る。放置は不成立(返却/没収)。手数料は無形資産だけ、お互いから成立額の何%。成立時の手数料を送金の手数料・1日の上限と同じ扱いにするかは未決。
- **運送クエスト(次)**: 非プライムの入荷は、運送クエストが終わると届く(システムが判定。プレイヤーのアンロック操作は無い)。プライムはオウムが運ぶので瞬時。報酬は専用口座の残高から(取り置き)。台帳は `market`(インフレに数えない)。
- 台帳: `exchange_buy`・`exchange_sell`(market。お金の移動)、`exchange_fee`(spend。専用口座の収入)。HRMHRMの常設出品の購入は `mail_order`(HRMHRMの収益)。

## 実装済み(0.5.6。UIなし。エンジンと確認用コマンド)
- `economy/exchange.js`: 価格の上限、HRMHRMの常設出品(郵便販売のカタログの通常の品。エンチャント本・エンチャントつきの品は対象外)、取引所プール、出品・取り下げ・期限、安い順の購入、売り手がオフラインの間の代金の保留、入荷(専用シュルカーへ。あふれ・未読み込みは入荷一覧に残る)、出荷(専用シュルカー → プール。名前・説明・エンチャント・傷みのある品は対象外)、日次の処理、専用口座。
- 政策パラメータ: `exchange_listing_fee_rate`(0.02)・`exchange_listing_days`(14)・`exchange_max_listings`(10)・`exchange_hrmhrm_refill_ratio`(0.25)。
- 確認用: `/scriptevent bmh:exchange pull|list|offers|buy|mine|cancel|pool|inbox|deliver|refill`。検算: `dev/check/check_exchange.mjs`。

## 実装済み(0.5.9。相場の統合・検索・価格・ボート)
- 相場(旧・ゴーレムの現物取引)を、取引所の常設の取引相手にした: 品目ページに「相場(システム)」の行(在庫は無制限)。買いは最安の出品から選ばれる(HRMHRM・プレイヤー・相場)。「相場で売る」は取引所プールの品を相場で売る。バルクの品はシュルカー1箱(1,728個)単位でだけ相場と取引する。1回の購入は5,184個まで。カード(リボ)はHRMHRMの分だけ(相場の分は残高)。台帳は commodity_buy/sell・bulk_buy/sell(market群。お金の出入りはシステムとの間)。
- 検索(`searchItems`): 日本語名・英語名・IDの部分一致。ひらがな/カタカナ/半角/大文字小文字の違いは無視。上位40件。
- 価格: レシピの無かった品を、似た品にならって追加。銅 < 鉄 < ダイヤ < ネザライトの段差。ボート11種を取引リストへ(295品)。
- 旧画面(ゴーレムのメニュー・価格のグラフ)は、取引所からは入れなくなった(コードは残してある)。相場のグラフ(週間)を取引所のページに出すのは未。

## 実装済み(0.5.11。村・会社の出荷 = 取引所への出品)
- 週の締めの出荷(村: 消費されない原料 / 会社: 保持数を超えた在庫)を、自動売却から取引所への出品に置き換えた。`economy/exchange.js` の `shipToExchange`。出品者は村・会社の口座(`sellerKind`: village / company)。売れた代金は、買い手の残高から村・会社の口座へ移る(新しく出るお金ではない。台帳は買い手側の `exchange_buy` のみ)。週の記録には `exchange_sales` として収益に入る。
- 単価 = 基準 × 掛率 × 出荷の掛け率(村 `village_ship_ratio` 0.8 / 会社 `company_ship_ratio` 0.8)。HRMHRMの売値を超えない。同じ品は1本にまとめる。売れ残りは期限(14日)で村・会社のプールに戻り、次の週に今週の値段で出し直す。取引リストにない品は従来どおり自動売却。切り替え `exchange_entity_shipping`(1/0)で、従来の動きに戻せる。
- 輸送費は村・会社には取らない(収支の再検算が済むまで)。`dev/check/check_village_economy.mjs` に「出品額(全部売れた場合)」の行を足した: 納品の代金の約20%(従来の自動売却と同じ)。ただし実際の収入は、プレイヤーが買った分だけ。
- NPC会社ができれば、会社同士・村との取引(p2p)になる。いまは、村・会社がプレイヤーに売る側。村が取引所で買う側になる(入荷を取引所の出品から調達する)のは未。

## 次(実装の順の案)
(1. UI は 0.5.7 で実装済み)
1. **UI**: 入口の置き換え(取引所のトップ・物品別リスト・品目ページ・購入・出荷一覧・入荷一覧)。カード払い(不足分はリボ)・プライムの引き継ぎ。
2. 郵便販売の旧入口・旧データの整理(エンチャント本・エンチャントつきの品の扱いを含む)。
3. 出品者を会社・村にする(出荷の自動売却を出品に置き換える。村の収支を再検算)。
4. 運送クエスト(非プライムの配送)。
5. 無形資産(オークション・保証金)。
6. 買い注文・常設買取(売りの受け皿)、モブショップのプレイヤー化、オススメコーナー。

## 未決
- 輸送費の額(いまは出品額の2%。運賃は量と距離で決めるべきという試算あり)。取り下げ時に返すか。
- 小口の上限・大口の境目。個人の出品の上限(いまは1人10件・1品目60件)。
- カード払いの扱い(取引所でも不足分をカードに回すか)。「手持ち + 預金」のうち、手持ちのエメラルドをどう使うか。
- 外貨建て(動物交易)を電子残高に寄せるか。モブショップをプレイヤーが置く条件。
- `quest_listing` との関係(別建てが優勢)。
