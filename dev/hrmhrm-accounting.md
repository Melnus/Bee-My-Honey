# HRMHRMの会計テンプレートと自動運用(2026-10-05。2026-10-06に開発銀行機構を分離)

実装: `scripts/economy/account.js`(口座テンプレート)・`scripts/economy/hrmhrm.js`(HRMHRMの会計と自動運用)。
検算: `node dev/check_hrmhrm.mjs scripts`。管理コマンド: `/scriptevent bmh:account [hrmhrm|list]`。

## 決定事項(作者の方針)
- 既存ワールドの資産は導入時に×64で換算する(既定。`migration.js`)。
- 口座テンプレートに**貴金属の時価評価を含める**。HRMHRMの会計は貴金属資産で裏打ちされている。
- 精算不能への介入ルール: **相手が3週を超えて精算不能なら介入**。村は人口が0なら登録解除、人口がいれば介入。法人は内容によりHRMHRMが介入(買い取り救済など)。
- 取引所のアプデは別にする。`quest_listing` と取引の出品を統合するかは保留。**まずHRMHRMが自動で動けるようにする**。
- (2026-10-06)HRMHRM単独ではなく、**法人はこの機能を元に派生する**。独立機関の開発銀行機構が申請を審査する(`development-bank.md`)。

## 口座テンプレート(`account.js`)
プレイヤー個人の口座とは別に、HRMHRM・村・法人が持つ「会社の口座」の型。1口座 = 1つの動的プロパティ(`bmh_acct_<id>`)。

| 項目 | 内容 |
|---|---|
| type | `hrmhrm` / `village` / `company` |
| cash | 現金(名目額E)。資金不足の間はマイナスになりうる(借越) |
| receivables / liabilities | 債権(貸出金など) / 負債 |
| holdings | 現物資産 `{ 商品キー: 個数 }`。時価評価の対象 |
| unsettledSince | 精算不能になった最初の週(解消で null) |
| population | 村の人口(村のみ) |
| weekly | 週次の締めの記録(直近26件) |

- **時価評価**: 保有する現物を、小口取引の相場(`getCommodityPrice`。基準×掛率×相場パターン×需要圧力)で評価。インフレで貴金属の評価額も上がる。
- **貴金属**: 金インゴット・ダイヤ(`PRECIOUS_METAL_KEYS`)。
- **貸借対照表**(`getBalanceSheet`): 資産 = 現金+債権+現物の時価、純資産 = 資産−負債。**裏打ち(coverage)** = 貴金属の時価 ×(1−掛け目10%)÷ 負債(負債0なら表示しない)。
- **介入の判定**(`decideIntervention`): 精算不能が3週を超えたら対象。村=人口0で登録解除/人口ありで介入、法人=介入、HRMHRM=対象外。登録解除した村の資産は誰も回収せず消え、「消えたお金」として別に集計する。
- **キュー**: 発行申請(`requestIssuance`)と介入案件(`queueIntervention`)を積む受け皿。発行機関・介入の処理が実装されるまでは、積むだけ。

## HRMHRMの会計(`hrmhrm.js`)
HRMHRMは現状「システム全体の相手方」として、プレイヤーとのお金のやり取りの反対側に立つ。発行台帳の週ごとの記録から、**週が終わるたびに**口座を締める。

| 区分 | 台帳のカテゴリ |
|---|---|
| 収益(プレイヤーが払った) | 郵便販売・プライム・保険料・事故補償・違約金・カード返済 |
| 費用(プレイヤーへ払った) | クエスト賃金・派遣マージン・雇用ボーナス・預金利息・配当 |
| 貸出(債権) | 融資の貸し出し(+)/返済(−)。返済が残高を超えた分は利息収益 |
| 借入(負債) | プレイヤーの融資の預かり(+)/返戻(−)。超えた分は利息費用 |
| **含めない** | 市場(ゴーレム・バルク・外貨・株・先物)との交換、換金(入出金・既存ワールドの換算) |

- 恒等式: HRMHRMの現金の増減 = −(含める流れでのプレイヤー側の純増)。お金は相手方どうしで保存される。
- 簡略化: カード払いの購入は現金が動かないので、収益は「カードの返済時」(現金主義)で認識する。市場は外部の相手方として扱う(市場での損益はHRMHRMに入らない)。
- 初期(暫定。ベース単位E。実際の金額は×掛率): 現金 4万、金 5万個、ダイヤ 2万個(貴金属は時価で合計約5.7万E相当 → 現金と合わせて資本金約9.7万E)。

## 自動運用(週ごとに1回。共通の運用 `entity-ops.js` + 開発銀行機構)
| 状況 | 動き |
|---|---|
| 現金が下限(2万E)を下回る | **自分では売らず**、開発銀行機構に資金を申請する(審査待ちの申請があれば重ねない)。審査で、売れる資産があれば却下して売却、なければ最低限の運用資金が支給される(`development-bank.md`) |
| 現金が上限(8万E)を超える | 目標を超えた分のうち、1週の売買枠(貴金属の時価の5%)の範囲で貴金属を均等に買う(HRMHRMだけ。`invest: true`) |
| 村・法人が3週超で精算不能 | 村=人口0なら登録解除、人口ありなら介入案件に。法人は介入案件に |

- 売買は相場に影響する(需要圧力。売買量の25%を反映)。売却を指示されると値下がりし、評価額も減る。
- 週の締めは「終わった週」を順に追いつく方式(日付が飛んでも、二重に処理しない)。
- すべての数値は暫定(`entity-ops.js` の `MANAGEMENT_PROFILES` / `HRMHRM_INITIAL`)。

## まだやっていないこと
- 開発銀行機構は実装済み(`development-bank.md`)。支給の返済・金利、審査理由の画面は未実装。
- 法人の介入の中身(買い取り救済か清算かの判断)。法人テンプレートの実装時に決める。
- 村・法人の口座の作成(登録の仕組みが無い)。口座の型・介入の判定・登録解除の処理だけ先に用意した。
- 株式の放出による資金繰り、市場にある品の生産による資金繰り(いまは「申請 → 売却 or 支給」まで)。
- 銀行預金をHRMHRMの負債として扱うこと(預金の総量は台帳がフロー方式のため、総量を持てない)。
