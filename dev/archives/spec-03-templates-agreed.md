#3(距離の概念とプールの追加) — テンプレート合意事項まとめ(9/28 ver)

■ trade_order(出品テンプレート)
- issuer / itemId or genreTag / unit / quantity / price / status / fulfillMode
  (fulfillMode: "shipment"物理納品 or "pool"プール加算)
- 生鮮市場では匿名版として流用
  - issuerは内部データとして保持(代金の入金先解決に使用)
  - UI表示のみissuerを伏せて出品番号に差し替える(表示層だけの匿名化)
- quest_listingとは統合可、違いは表示モード(公開/匿名)だけ、で決着

■ trade_pool(集計テンプレート)— 2形態に分岐
- shop型(例:Paws & Blackpots)  … 単一itemIdの実在庫カウンタのみ
- exchange型(例:生鮮市場)      … genreTag配下の複数trade_orderを集計
                                    +価格推移の時系列を保持
- 実装イメージ:poolType: "shop" | "exchange" でモード分岐

■ trade_post(拠点)
- 事前登録は不要と判明。交易ブロックは既に物理設置済みなので、
  納品/取引の都度その場の座標のバイオームをその場で照会すればよい
- 「設置者以外は壊せない保護機能」は今回は見送り、
  セキュリティ周りをまとめて実装するタイミングに後回し

■ 生鮮市場アーキテクチャ
- 旧:世界共通の匿名共有プール → 新:trade_order方式のオーダーボード
- 商品(魚種)ごとに1ページ(上部:価格推移グラフ／下部:出品リスト
  [出品番号・価格・産地バイオーム名産・安い順]／巡回のたびに古い出品を除去)
- 対象は「生鮮物=食べ物」のみで確定(シーピクルス・サンゴ・プリズマリン系・
  オウムガイ・海の心は装飾品のため元々対象外)
- 納品モーダルでグラフ+予想価格帯をサジェスト、最終価格はプレイヤーが入力(強制ではなく目安)
- 価格目安は産地バイオームのregion:*タグで機械的に決定(水辺に近い=安い、遠い=高い)

■ quest_listing(クエストテンプレート)— 5種類のquestTypeに整理
- 1つのテンプレートにquestTypeタグを持たせる形(型ごとに別テンプレートにはしない)
- delivery / defeat / arrival / action / score の5種類
  - プロテクト型・所持型(nameTagチケット方式)は独立させず action に寄せて吸収
  - score型のみイベント駆動ではなく既存の週次ロールオーバーでスナップショット判定
- 実際に何を求められるかはマルチサーバー運用しないと分からないため、
  今は起こりえそうな型だけ先回りし、それまでは村人・モブ自動発生のクエストで繋ぐ方針
- 詳細な実装ガイド(型ごとのrequirement書式・追加手順)は別ファイル(quest-guide.md)に切り出し済み

■ 持ち越し(v0.4.1時点では両方とも決定済み)
- region:*タグの段階粒度 → 3段階(region:coastal / region:inland / region:remote)。バイオームIDからの静的マッピング(tag-dictionary.jsのBIOME_REGION_MAP)。バイオームIDの実機突き合わせは未実施
- 実際のデータファイル配置 → labor.js拡張の方針(quest_listingは元々labor.js内蔵で、労働市場の下位概念だったため)
