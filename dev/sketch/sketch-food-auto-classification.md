# スケッチ: 食品の自動分類(鮮度区分の自動判定)

状態: **構想メモ(未着手・0.4.2では実装しない)**
作成: 2026-09-29
関連: `data/food-data.js`、`data/item-dictionary.js`、`economy/freshness.js`、`MILESTONES.md`の「既知のバグ・課題」

ここに書いた案は、ドキュメント確認と机上の検討だけで、実機での検証はしていない。

---

## 1. 目的

- 手動の3リスト(`RAW_FOOD_ITEMS`/`PROCESSED_FOOD_ITEMS`/`NEVER_SPOIL_ITEMS`)を、機械的に作れる部分から減らす
- サーバーのカスタムアイテム(MOD食品、他アドオンの食品)も、利用者に登録させずに鮮度の対象にする
- 「焼いたら伸びる」(生→加工品で寿命が延びる)を、かまどの調理を検知せずに近い形で再現する

## 2. 現状(v0.4.2)

- `getFoodCategory(typeId)`は3リストにあるIDだけ区分を返し、それ以外は`null`
- `freshness.js`は`null`を非食品として飛ばすので、未登録の食品(カスタム含む)は腐らない
- `food-data.js`のコメントには「未登録はRAW扱い」とあるが、実装されていない

## 3. 基本方針

- **利用者に登録させない**(カスタムアイテムは自動認識)
- **「認識」と「値付け」は別**: 鮮度は既定値で自動化できる。価格・ジャンルは自動で決めない(辞書にない品は取引対象外)
- **安定版APIだけで動く判定を土台にする**。ベータAPI(クラフトイベント等)は任意の後付け
- 手動リストは「自動判定の例外指定」に縮める

## 4. 判定の流れ(案)

上から順に見て、最初に当たった区分を採用する。

1. `NEVER_SPOIL`(例外リスト・自動判定の腐らない表)→ 対象外
2. `PROCESSED`(表またはID命名の判定)→ 12日
3. `RAW`(表)→ 6日
4. どれにも当たらず、食べ物と判定できる → 既定区分(RAWか加工か。要決定)
5. 食べ物と判定できない → 対象外

### 4-1. 事前生成テーブル(バニラ)

開発時にバニラのデータ(下記5章)から、次の表を作って`food-data.js`に焼き込む。

| 表 | 作り方 |
|---|---|
| バニラ食品の全一覧 | `minecraft:food`コンポーネントを持つアイテム |
| 加工品 | かまど・燻製器・焚き火のレシピで、出力が食べ物のもの / クラフトレシピの出力が食べ物のもの |
| 生 | 食品一覧から加工品と腐らない品を除いたもの(要目視確認) |
| 腐らない | 材料に砂糖・金系素材を含む食品(ケーキ・パンプキンパイ・金のリンゴ等)。クッキーは砂糖を使わないので例外指定 |

### 4-2. ID命名による判定(カスタム食品向け・目安)

- IDに`cooked`・`baked`・`roasted`・`grilled`・`smoked`・`steak`・`dried`・`stew`・`soup`等の語が入っていれば加工品扱い
- 語のリストは`food-data.js`に置き、後から足せるようにする
- 外れたとき(命名に語がない焼き肉)は、加工品なのに6日で腐るだけで、壊れはしない
- 例: 生の「クマの肉」は6日、「クマのステーキ」は12日

### 4-3. 食べ物かどうかの判定(要確認)

- 食品コンポーネントの有無で判定する想定。対応バージョンで読めるかは未確認
- 読めない場合は、未登録の品を対象外のままにする(現状維持)

## 5. 調べること(次にやること)

- 公式サンプルのリポジトリ(`bedrock-samples`)を落として、次を抽出する
  - `minecraft:food`を持つアイテムの一覧
  - かまど・燻製器・焚き火のレシピ(入力→出力)
  - 出力が食べ物のクラフトレシピと、その材料
- 抽出結果と現在の3リストを突き合わせ、抜け漏れと区分のズレを洗う
- 対応バージョンで、スクリプトから食品コンポーネントを読めるかを確認する
- (任意)クラフト完了イベントが作業台で発火するかを、ログ出力だけのスクリプトで確認する

## 6. 未決事項

- 未登録の食べ物の既定区分(RAW=6日 / 加工=12日)。コメントの想定はRAW
- 命名判定の語リストの範囲(誤判定を避けるため、最初は少なめにする)
- 他の腐敗系アドオンとの併用: 対象外にする / サーバー設定で鮮度をオフにできるようにする
- クラフトを経た食品の鮮度の扱い(新品に戻る問題。材料の最も古いスタンプを引き継ぐ案)
- 腐らない判定で、砂糖・金以外の素材(ハチミツ系など)を含めるか

## 7. 不採用にした案

- **材料の個数・種類数で判定**: 腐らないでほしい5種と、腐ってほしい料理(シチュー・パン等)の境目がきれいに分かれない
- **利用者による登録(登録ガイド)**: サーバーでは非現実的
- **他アドオンのようにカスタムアイテムへ差し替える方式**: バニラ食品の置き換えが必要になり、BMHの辞書(価格・ジャンル・鮮度)がそのまま引けなくなる
