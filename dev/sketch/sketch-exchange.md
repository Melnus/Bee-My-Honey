# スケッチ: 取引所(2026-10-19、未採用)

作業スキーマ(スケッチ → 〇〇Guide.md → 本採用)の最初の段階。決定事項と「案」を分けて書く。
前提: `dev/MILESTONES.md` の ④(P2P共通基盤と取引所)、`dev/sketch/sketch-org-needs.md`(村・会社の需要)、`dev/village-company-flow-spec.md`。

## 決定事項(作者の方針)
- 取引所は**入口を1つ**にする。開くと全品のリストが見える。品目ごとに取引の方式を持ち、生鮮なら生鮮の方式、現物のリストにある品なら現物の方式で取引する。
- **現物取引(ゴーレム)と郵便販売(Skein)は統合する。**
- **モブショップ(動物交易・Paws & Blackpots)は、プレイヤーが建てられるようにする。**
- **確実にある分はHRMHRM発行**(常設出品)。それより安く、使いやすくするために、会社・村が出す(会社をみんなで建てる、村から出荷される)。
- **小口はプレイヤー優先、大口は村と会社。** 個人は1シュルカーまで、それ以上は法人格が必要(既存の予定)。
- スタッフサービスはクエスト(プレイヤーの窓口)であり、取引所ではない。
- 村・会社の赤字は取引所ができてから見直す(出荷を自動売却ではなく出品にする)。

## 前提(いまのコードにあるもの)
- `economy/trade-pool.js`: shop型(単一品目の実在庫カウンタ)と exchange型(ジャンルの下に複数の出品)。`fulfillMode`(`shipment` / `pool`)の考え方がある。
- `data/mail-order-data.js`: `MAIL_ORDER_STANDING_STOCK`(HRMHRMの常設出品数)。
- 現物取引(`economy/trade.js`): 相場が動く(週間パターン + 需要圧力)。バルクはシュルカー単位。
- 郵便販売(`economy/mail-order.js`): 基準価格 × 1.25 の固定価格 + 日替わり特売。
- 動物交易・PB: 外貨建て。PBは実在庫制。生鮮市場: exchange型で鮮度つき。
- 台帳(`ledger.js`)、政策パラメータ(`policy.js`)、村・会社の口座と在庫。

## 案(未確定。検討のたたき台)

### 1. 品目表と取引の方式
- 全品を1つの品目表に載せ、品目ごとに**取引の方式**(仮)を持たせる。
  - `fresh`: 生鮮(exchange型 + 鮮度)
  - `spot`: 現物の小口(希少資源など)
  - `bulk`: 現物の大口(シュルカー単位。法人のみ)
  - `mail`: 配送品(カタログ。足元ドロップ)
- 取引所の画面は「全リスト → カテゴリ → 品目 → 出品の一覧 → 購入/売却」。方式の違いは、購入の確認画面と受け渡し(足元ドロップ / 配送 / 在庫)に出る。

### 2. 出品者の種類
- HRMHRM(常設・実在庫制)/ 会社 / 村 / プレイヤー(小口)。
- 出品の形(仮): 出品者(種類・ID)・品目・数量・単価・方式・期限。
- 単価は出品者が決める。HRMHRMの常設出品だけは、価格エンジンの式(基準 × 掛率 × 需要圧力)で決まる。

### 3. 価格の枠
- HRMHRMの売値が、購入側の**上限**になる(これより高い出品は選ばれない)。
- 需要圧力は、HRMHRMの価格にだけ効かせる。プレイヤー・会社・村の出品には掛けない(出品者が自分で決めるため)。

### 4. 売りの受け皿
- 買う側は上の通りだが、売る側は誰が買うのかが要る。
- 候補: (a) HRMHRMの常設買取(低め。買った分は実在庫として常設出品に積む。いまのプール換金の置き換え)/ (b) 村・会社の買い注文(いまの村・会社のクエストの需要を、買い注文として出す)。
- (a)(b)を両方入れると、HRMHRMの買値と売値の間でプレイヤーが取引できる。

### 5. 小口と大口
- **小口**: 個人が主役。1回の取引は1ロット以内(上限は未決。64個案)。
- **大口**: シュルカー単位。出品も買い注文も、会社・村(法人格)のみ。個人は1シュルカーまでの既存の制約をそのまま使う。
- 個人から大口への道は、**村・会社のクエストへの納品**(→ 会社・村の在庫 → 大口の出品や出荷)。クエストは取引所と競合せず、個人から法人へ渡すパイプになる。
- HRMHRMの常設出品は、小口では薄くする(実在庫制、補充は日量の上限つき、価格は高め)。無限に安く出すと、プレイヤーの出品が成り立たない。

### 6. モブショップのプレイヤー化
- shop型の出品者を、HRMHRMからプレイヤー(または会社)に広げる形。出品は実物を納品して店の在庫に入れ、価格は店主が決める。
- 外貨は、売買で動くだけにする(外貨を無から出さない)。いまの動物交易・PBの「外貨を無から出す」処理は、ここで置き換える。
- 未決: 設置の条件(会社のみ/個人も)、動物を実際に置くか、窓口のブロックだけか。保有施設(範囲登録)との関係。

### 7. 村・会社の出荷
- 週の締めの自動売却(`village_ship_ratio`)をやめ、出品に置き換える。価格は村・会社の側が決めるが、既定は価格エンジンの式から。
- 出荷が相場で売れるので、村の収支は、ここで再検算する(`sketch-org-needs.md` の収支検算を、出荷を相場で売る前提に切り替えて回す)。

### 8. 旧入口の扱い
- ゴーレム(鉄ブロック + 植木鉢)、郵便販売(書見台 + 紙)、動物の窓口(各ブロック + 植木鉢)をどうするか。
- 候補: (a) 取引所に一本化して旧入口は廃止 / (b) 旧入口から取引所の該当カテゴリへ入れる(移行期間)。既存ワールドの移行も要る。

## 未決(取引所のアプデに着手するときに決める)
1. 取引所の入口のブロック(既存の入口の統合か、新設か)
2. 小口の上限、大口の境目
3. 売りの受け皿の形((a)(b)のどちらか、両方か)
4. `quest_listing` と出品を**統合するか別建てか**(傾向: 別建て。村・会社の需要が買い注文になり、取引所は組織・個人・外部の主体が並ぶ場にしたいため)
5. モブショップをプレイヤーが設置する条件
6. 外貨建て(動物交易)を、外貨のまま残すか、電子残高(E)に寄せるか
7. 手数料(出品・成約)の有無と、台帳のカテゴリ
8. 旧入口の廃止時期、既存ワールドの移行
