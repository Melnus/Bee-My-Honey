# 開発銀行機構(2026-10-06)

実装: `scripts/economy/dev-bank.js`(審査)・`scripts/economy/entity-ops.js`(口座を持つ主体の共通の運用)・`scripts/economy/account.js`(口座テンプレートと申請のキュー)。
検算: `node dev/check_devbank.mjs scripts`。管理コマンド: `/scriptevent bmh:devbank`(判断の履歴)・`/scriptevent bmh:account`(HRMHRMの貸借対照表+開発銀行)。

## 位置づけ(作者の方針)
- HRMHRM単独の機能ではなく、**法人はこの機能を元に派生する**。口座テンプレート・共通の運用・資金の審査は、HRMHRM・村・法人が同じものを使う。
- 開発銀行機構は**HRMHRMや法人から独立した機関**として生きている。申請元の資産を見て、売りに出せそうなものがあれば**申請を却下して資産を売りに出させ**、なさそうなら**最低限の運用に必要な分を支給**する。

## 構造
```
口座を持つ主体(HRMHRM / 村 / 法人)        account.js が共通のテンプレート、entity-ops.js が共通の運用
   │ 週ごとの運用: 現金が下限を割る → 自分で資産を売らずに「資金の申請」を出す
   ▼
開発銀行機構(dev-bank.js。独立機関)          週ごとに申請を審査
   ├ 売れる資産がある → 却下。資産を売却させる(貴金属以外 → 貴金属。必要な額まで。相場に影響)
   ├ 売れる資産がない → 最低限の運用資金を支給(新しく発行するエメラルド。上限あり)
   └ 支給の必要がない → 支給なし(申請を閉じる)
```
HRMHRM専用なのは、初期の資本金と、台帳から週の収益・費用を作る部分(`hrmhrm.js`)だけ。

## 審査のルール
| 項目 | 内容 |
|---|---|
| 売れる資産の判定 | 申請元の現物(商品)の時価(3%引き)の合計が、`devbank_min_sellable_base`(既定500E・ベース単位)以上 |
| 売却の順番 | 貴金属以外 → 貴金属(金・ダイヤの裏打ちを最後まで残す)。主体ごとの目標の現金(HRMHRMは4万E・ベース)になるまで |
| 売却のあと | 申請は「却下(売却)」で閉じる。まだ足りなければ、次の週に再申請 → その時点で売れる資産がなければ支給 |
| 運用に必要な資金 | 直近4週の週あたり費用の平均 × `devbank_operating_weeks`(既定4週)。費用の記録がない主体は下限(2,000E・ベース) |
| 支給額 | 運用に必要な資金 − 現金。1回あたり `devbank_grant_cap_base`(既定20万E・ベース)が上限。必要がなければ支給なし |

## 判断基準のパラメータ(将来のプレイヤーの議論の対象)
`devbank_operating_weeks` / `devbank_grant_cap_base` / `devbank_min_sellable_base` は `policy.js` に登録してあり、金利と同じ安全装置(範囲・1回の変更幅・1週に1回・履歴・購読)で変更できる。
(`/scriptevent bmh:policy list` に出る。)

## お金の数え方
- 支給は申請元の口座に入るだけ。プレイヤーに渡るのは、申請元がそれを使った時(台帳の income など)。
- そのため、インフレの入力(台帳の純増。`inflation.js`)には**支給を数えない**(二重に数えないため)。支給の累計は `getDevBankState()` に別に持つ。
- 「お金を新しく作る」のは、厳密には この支給(と初期の資本金)。いまの「発行台帳の income」は、HRMHRMからプレイヤーへの支払い(移転)で、活動量の目安として使い続けている。

## 週次の流れ
各口座の週の締め → 運用(申請を出す / 余剰なら貴金属を買う)→ 開発銀行機構が申請を審査 → 精算不能の介入の判定(3週超。村は人口0なら登録解除・人口ありなら介入。法人は介入)。

## まだやっていないこと
- 法人の介入の中身(買い取り救済か清算か)。法人テンプレートの実装時に決める。
- 株の放出による資金繰り、市場にある品の生産による資金繰り(売却と支給の2段まで)。
- 村・法人の口座の作成(登録の仕組み)。型・申請・審査は用意済みで、HRMHRM以外はテストでだけ動いている。
- 支給の返済・金利(いまは贈与。融資型にするかは未決)。
- 審査の理由をプレイヤーに見せる画面(いまは管理コマンドだけ)。
