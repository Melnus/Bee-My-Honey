# Bee-My-Honey 開発規約

新しいセッション(このプロジェクトを初めて触るClaude)は、コードを書き始める前に必ずこのファイルを読むこと。
別セッションで作業を引き継ぐ際は、まずこのファイルをプロンプトに貼るか、フォルダごと渡して「まずCONVENTIONS.mdを読んで」と伝える。

## 1. 多言語対応(i18n)は必ず strings.js に一元化する

- 表示文言を追加するときは、その場に `{ ja: "...", en: "..." }` を直書きしない。
- 必ず `scripts/i18n/strings.js` の `STR` オブジェクトに追加し、呼び出し側では `t(lang, STR.xxx)` を使う。
- 例外として `scripts/ui/labor-menu.js` にローカル関数 `L(lang, ja, en)` が存在するが、これは規約違反の残骸であり将来的に廃止予定。**新しいコードで真似しない。**
- 新しい文言を追加したら、`strings.js` の同じセクション(配当関連なら `div〜` の並び)に揃えて追加する。

## 2. 新しい enum 的な値(タイプ/フラグ)を追加したら、参照箇所を全部洗い出す

例: `dividendType: "cash" | "stock_option"` のような新しい種類の値を追加するとき。

- 追加する前に `grep -rn "dividendType" scripts/` のように既存の全参照を洗い出す。
- 新しい値を追加したら、**その値を分岐しているすべての箇所**で実際に動作確認する(1箇所だけ直して満足しない)。
- 特に「新しい値のときだけ通る分岐」は、他の値では絶対に通らないので気づかれにくい。優先的にテストする。

## 3. 実装後は必ず未定義参照チェックをかける

このプロジェクトにはESLintは入っていない(npm registryへのネットワークアクセスがサンドボックスで制限されている環境がある)ため、
代わりに `check_undefined.js` という簡易スキャナを使う。

```
node dev/check_undefined.js scripts
```

- 何か実装・修正した後は、コミット(=ユーザーに渡す)前に必ずこれを実行する。
- ジェネレータ関数(`function* foo()`)は誤検出することがあるので、報告が出たら鵜呑みにせず中身を確認してから報告する。

## 4. Promiseの `.catch` でエラーを握りつぶさない

`form.show(player).then(...).catch((e) => console.warn(...))` という形が多用されているが、
`console.warn` だけだとプレイヤー側は「反応しない」としか見えず、バグ発見が遅れる。
UIが絡む新しい分岐を書いたら、実際にゲーム内でそのボタンを押して確認するまでを実装のセットとする。

## 5. セッション引き継ぎ時のチェックリスト

別セッション(制限に引っかかったメイン開発セッションなど)から作業を引き継いだときは、対応前に:

1. このファイル(CONVENTIONS.md)を読む
2. 変更したいファイルだけでなく、関連ファイルを `grep` で洗い出す(1.と2.参照)
3. 変更後に `check_undefined.js` を実行する
4. 変更点を1〜2行で要約してユーザーに報告する(「何を」「なぜ」「どこを直したか」)
