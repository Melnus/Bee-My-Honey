# 統一プライシングエンジン・ガイド(本採用、2026-10-02)

`village-baseline.md`(賃金算定)の続き。0.4.2→0.5.xロードマップの「価格のオーバーホール」
全体(クエスト・郵便販売・バルク・各モブの店)に共通する、唯一のプライシングエンジンとして
位置づける。3層構造。

## 第1層: 原価

```
採集素材の原価 = 労働費
  = 村の最低賃金(village-baseline.mdで算定済み) ÷ 1日あたりの採集数

加工品の原価 = 材料原価(レシピを1段階ずつ再帰的に辿って合計)
            + 加工労働費
            + 明示できる追加コスト(燃料代など、個別に根拠がある場合のみ。多くの品目ではゼロ)
```

加工労働費は「クラフト1回が瞬時かどうか」ではなく、**何百個と作る時にかかる実際の手間**
(クラフト台のUI操作を繰り返す時間)を指す。採集と同じ式で、分母だけクラフト用の
デフォルトを別に置く:

```
加工労働費 = 村の最低賃金 ÷ 1日あたりのクラフト可能数
```

デフォルトのクラフト可能数: **640個/日**(採集デフォルトの10倍)。

### 1日の基準: 60分(確定)

採集(64個/日)・クラフト(640個/日)はこの60分基準で検算できる
(採集は1個あたり約56秒、クラフトは約5.6秒。移動・採掘動作を含む採集の方が遅いのは自然)。

### 製錬系(実時間から直接計算、確定)

分子の「村の最低賃金」は、特定の採集物に紐付かない汎用部分(手間賃10E)を使う。

```
加工労働費(製錬) = 10E ÷ (60分 × 60秒 ÷ 1個あたりの精錬秒数)
追加コスト(燃料) = 村の床値(石炭 0.1E、釣り人レート) ÷ 8個(石炭1個=8個分の目安)
```

| 職業ブロック | 精錬秒数/個 | 精錬数/日 | 労働費/個 | 燃料費/個 |
|---|---|---|---|---|
| かまど(職業ブロックでない) | 10秒 | 360個 | 0.028E | 0.0125E |
| 溶鉱炉(鉱石・一部装備のみ) | 5秒 | 720個 | 0.014E | 0.0125E |
| 燻製器(食物のみ) | 5秒 | 720個 | 0.014E | 0.0125E |
| たき火(職業ブロックでない、燃料不要) | 30秒 | 120個 | 0.083E | 0円 |

採集素材は「村の床値テーブル」を使わず、労働費だけで原価を出す(床値が無い素材でも
計算できるようにするため)。村の床値(village-baseline.mdのテーブル)は、HRMHRM賃金が
「村の最低賃金を下回っていないか」の検算に使う役割に限定する。

### 再帰のルール(重要、2つ)

1. **再帰では必ず「原価」(第1層)だけを積み上げる。1.20倍(第2層)は最終的な完成品に
   1回だけ適用する。** 中間素材ごとに基準価格を使って再帰すると、1.20が何重にも掛かって
   最終価格が不当に膨らむ(マージンの二重掛け)。
2. **既に`COMMODITIES`に`baseRate`が存在する素材(鉄インゴット・トウヒの原木等)は、
   採掘/伐採から再帰計算せず、その`baseRate`をそのまま材料原価として使う。** 同じ素材に
   「市場価格」と「再帰計算した原価」という2つの違う基準が生まれるのを防ぐため。
   `COMMODITIES`に無い素材だけ、労働費からの再帰計算に進む。

### 採集素材の「1日あたりの採集数」: 64個/日(確定)

丸石・小麦は`UNQUALIFIED_JOBS`に実データがある(採掘48個/日、農家12個/日)が、これは
あくまで「クエストとして無理のない納品数」であって、採集ペースの実態ではない。
汎用デフォルトは**64個/日(1スタック)に確定**。根拠:

- あくまでバニラの村基準(=村人のレベル上げペース等)に合わせる。中央値のような
  統計的な丸めより、1スタックという区切りの良い基準の方がバニラの感覚に合う
- プレイヤーの自動化(全自動農場・自動採掘など)を基準に組み込むと、原価が際限なく
  下がって経済が成立しなくなる。**自動化は考慮せず、手作業の基準として64個/日に固定する**

原木・鉱石など、仕事テーブルに無い素材もこの64個/日を汎用デフォルトとして使う。

**ただし、希少資源(ダイヤモンド・エメラルド・ネザライト関連等)は後回しにできる話ではなく、
この仕組みを使う前に個別の採集数で上書き必須のリストとして扱う。** 汎用64個/日をそのまま
当てはめると丸石と同じ労働費になり、明らかに安すぎる価格が出てしまうため。

## 第2層: 基準価格

```
基準価格 = 原価 × 1.20
```

固定マージン20%。クエスト報酬・郵便販売価格・バルク/モブの店の初期価格は、全てこの
基準価格を土台にする。

## 第3層: 市場価格

実売価格は需要・供給で変動する。**新規実装は不要で、既存の仕組みがそのまま第3層にあたる**。

- 合成市場(#1の`COMMODITIES`、`getBulkCommodityPrice`等) → 需要圧力(`commodity`/`commodity_bulk`
  カテゴリ)による変動が既に実装済み。`baseRate`を第2層の基準価格に合わせて検算すればよい
- 生鮮市場(`fresh-market.js`) → 実出品の需給(プレイヤーが入力する価格)がそのまま第3層
- 郵便販売・クエスト報酬のような「常にHRMHRMが固定価格で出す」ものは、当面は
  第2層(基準価格)をそのまま実売価格として使う(変動させる仕組みが無いため)
- PBは例外。既にネコの気まぐれ(日替わり0.7〜1.6倍、`pb-data.js`の`PB_PRICE_FACTOR_MIN/MAX`)
  という変動機構を持っているので、`basePrice`を第2層(基準価格)の算出値に置き換えるだけで、
  既存の気まぐれ変動をそのまま第3層として使う

## 適用範囲

ロードマップの4項目全部がこの第1層・第2層で計算し直せる:

1. クエスト報酬(`dev/sketch/village-baseline.md`で算定済みの賃金が、採集素材の労働費の
   土台そのものなので、ここは実質済んでいる)
2. 郵便販売価格(`mail-order-data.js`。「現実の金銭感覚の桁」方針は撤回済み。加工品が多いので
   再帰的な原価計算の主戦場になる)
3. バルク取引(`#1`の`COMMODITIES.baseRate`)
4. 各モブの店(PB等の`basePrice`)

## 決定事項まとめ

1. 採集デフォルト: **64個/日**(希少資源は個別上書き必須)
2. クラフトデフォルト: **640個/日**
3. 1日の基準: **60分**
4. 製錬系: 実時間から直接計算(上表)。燃料費は村の床値(石炭)から算出
5. 再帰ルール: 原価だけを積み上げ、1.20倍は完成品に1回だけ。既存`COMMODITIES`の
   `baseRate`がある素材はそれを優先し再帰しない
6. 利益率: 基準価格 = 原価 × 1.20(固定)
7. 第3層(市場価格)は新規実装不要。合成市場は既存の需要圧力、生鮮市場は実出品の需給、
   PBは既存のネコの気まぐれ変動、郵便販売・クエスト報酬は当面基準価格をそのまま使う
